# Exact-rank continuation policy

A rank is advanced only after the recorded prior-rank coverage audit reports no missing/duplicate completed roots and no positive candidate. The rank9prepare step reads the immutable rank8audit, verifies all seven seed hashes, then resumes each rank9candidate order from the separate old rank9completed prefix. It never treats an interrupted root as closed. Four modulo4suffix shards per parent each have150nativeCPU caps, preserving the previous contiguous prefix. Full candidate orders are compared literally in every worker. Native greedy-color repair pruning has independent arbitrary-graph, known-goal and small actual-code coverage tests.

Six rank8families are unfiltered strict searches; one uses known-goal filtering. Rank9has five unfiltered and two filtered families. Filtered completion only concerns the explicitly enumerated connected goal bundles and saturated pools. A rank-local native computation is not global optimality or a formal independent absence certificate. Both positive acceptance checkers remain unchanged.

Actual CPU can be far below the nominal allowance when a shard closes. The policy is an exhaustion-driven untrained rule, not a claim that Tinker has learned to improve code size.
